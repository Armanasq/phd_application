# heyulanKiara/django-phd-scholarship — exclusion plus source-level audit

- Date: 2026-11-12. Revision: [5b7b61549e5ceffa38809759df4d41f6bb702380](https://github.com/heyulanKiara/django-phd-scholarship/commit/5b7b61549e5ceffa38809759df4d41f6bb702380).
- Canonical screening: SCREENED_EXCLUDE, code ENROLLED_STUDENT_SCHOLARSHIP_NOT_ADMISSIONS.
- Secondary verdict: reject as a deployable internal system; substantial API/model drift and unsafe development settings.
- Review modality: source-level, static; no MySQL/Django runtime tests executed.
- Scope: 34 tracked files and one recorded initial commit, Dec 3, 2025, no retrieved PRs or issues.

## 1. Domain and explicit inclusion boundary

Despite its title, the [Chinese source requirements](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/requirement.txt) describe a **post-matriculation** scholarship allocation system for already-enrolled full-time doctoral students: apply for internal TA/RA positions, track verified work, determine stipend additions/deductions, perform internal administrative reviews and appeals. It provides no external PhD recruitment calls, 2026/2027 doctoral admissions portals, supervising principal-investigator vacancies or foreign student funding eligibility. The admissions discovery candidate is thus a domain keyword false positive, not a failed admissions crawler.

## 2. Architecture and source coverage

The [Django models](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py) define Department, AdminUser, Student, Position, Application, Assignment, WorkLog, Workload, Scholarship, AdmissionCriteria, Score, Notification, FilterRule, IssueCriteria, Objection and Publicity. [API routing](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_urls.py) and [2,437-line API views](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_views.py) expose student login/profile and internal applications, work log review, annual scholarship calculations, admin configuration, exports, reports, notifications, identity verification and public announcements. The [site routes](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/urls.py) also expose minimal Django template pages. The code uses a local MySQL connection, Django sessions and direct JSON endpoints. Staff permission checks exist on several administrative endpoints; no blanket claim that every admin route is publicly accessible is justified.

Useful conceptual entities include a position separate from an application, an accepted assignment with work periods, annual funding record, and an internal review status. Yet these represent internal payroll/assistantships and should never be conflated with incoming PhD admission or legally binding funded employment offers.

## 3. Source-confirmed API/model inconsistencies

Several active API handlers request ORM attributes which do not exist in the pinned models. These are concrete integration defects, not merely undocumented features:

- [Admin application review](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_views.py) creates and filters Workload using student, position, amount, workload_type, year, status and verified_by. [Workload](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py) defines assignment, year_start/end, period, hours, adjusted_hours and evaluation fields instead; it has no those direct student/position fields.
- The APIs frequently use application.application_id and scholarship.scholarship_id even though [Application and Scholarship](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py) declare primary key id.
- [Data sync](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/data_sync.py) writes Score.type, source_id, source_name and value, but [Score](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py) holds student, year, coursework_score, research_score, attitude_score and extra_info.
- [Scholarship creation](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_views.py) reads IssueCriteria.is_active, min_workload and reward_coefficient and Workload.total_workload, while [IssueCriteria and Workload](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py) provide min_workload_hours, bonus_rate, hours and adjusted_hours instead.
- [API view module](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_views.py) defines notification listing/read functions twice; the later definitions refer to Notification.student, but [Notification](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py) relates to User via user.
- Views use Position.supervisor after [migration 0003](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/migrations/0003_remove_position_supervisor_remove_student_supervisor_and_more.py) explicitly removed that field. Server views also refer to untracked position/application templates. This contradicts [IMPLEMENTATION_SUMMARY](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/IMPLEMENTATION_SUMMARY.md) assertions of a complete functioning workflow.

The [test_api.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/test_api.py) demo invokes legacy route names, sets up mutable records and does not verify the active API contract. Other test scripts exist, but no executed test result or CI pipeline was established. Not all endpoints necessarily fail; the findings identify specific demonstrated mismatches when the corresponding paths are used.

## 4. Identity, privacy, and policy risks

- [settings.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/phd_scholarship/settings.py) **commits a literal Django secret key and MySQL root password**, with DEBUG enabled. Sensitive values are intentionally not reproduced in any PhD Atlas artifact. If these settings were deployed, credentials must be rotated and history managed.
- Most modifying API views use csrf_exempt although authentication uses session cookies, defeating Django's normal CSRF protections on those paths. Admin authorization on some routes does not mitigate CSRF by itself.
- [Student profile POST](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_views.py) permits a student to change wage, full-time and enrollment status fields directly, without a separate administrative proof workflow. Authoritative eligibility must not depend on such self-editable attributes.
- The [mock data sync](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/data_sync.py) generates **random** courses, grades, training status and research outputs, and exposes that service through an administrator-triggered sync route. The repository explicitly calls it a mock. Persisting such values as institutional evidence would be methodologically unsound even if the current ORM mismatches were repaired.
- Student bank account values and transcripts/CVs are represented in [models](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py); no production privacy, retention, external storage audit or independent role isolation was verified.

## 5. Evidence and limited transfer

Examined the full tree, [requirement.txt](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/requirement.txt), [models.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/models.py), [api_views.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_views.py), [api_urls.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/api_urls.py), [data_sync.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/data_sync.py), [data_export.py](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/data_export.py), [settings](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/phd_scholarship/settings.py), [migration](https://github.com/heyulanKiara/django-phd-scholarship/blob/5b7b61549e5ceffa38809759df4d41f6bb702380/core/migrations/0003_remove_position_supervisor_remove_student_supervisor_and_more.py), templates/views and all three test scripts, GitHub history and issues/PRs. No raw applicant data, production DB, actual university information system, credential, SMTP endpoint or deployment was accessed. No tests run; the review does not prove an exploit.

Potential reuse is limited to **model boundaries** between person, internal assignment, work log, scholarship payment and review event. Actual incoming doctoral funding should instead be modeled as separate employer job, scholarship award and country-specific tuition/visa categories with official claim-level evidence. Exclude this repository from the **admissions evidence inventory** while retaining the source audit as a negative-control research artifact.
