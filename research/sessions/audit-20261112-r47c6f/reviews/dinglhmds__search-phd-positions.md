## 1. Purpose and source context

The application receives a university name, searches CS faculty directories, extracts information from one crawler response with an LLM, stores faculty JSON and lets an applicant create cold-email drafts. The inspected May 3, 2026 revision includes two active cached data exports plus historical extracts. No license file, CI workflow or automated active test suite was found. The university alias YAML contains 274 records, not the 800+ described in the stale [AGENTS](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/AGENTS.md); that guide also describes the prior monolithic HTML layout rather than the current templates. An academic affiliation in these examples does not establish present recruiting, funding or a vacancy.

## 2. Architecture and task-to-data flow

[main.py](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/main.py) accepts POST /scrape, calls [PlannerAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/planner_agent.py) for an alias-to-domain YAML lookup or LLM inference, [SearchAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/search_agent.py) to query SerpApi using a site restriction, [CrawlerAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/crawler_agent.py) to visit **only the first** search result, then [ParserAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/parser_agent.py) to extract faculty attributes through a SiliconFlow-backed LLM. The parser partitions Markdown into chunks up to 8,000 characters and executes up to eight threaded calls; output is JSON with name, title, research areas, email and homepage. The file is saved at runs/{university}_parsed.json. Existence bypasses a new crawl indefinitely; there is no freshness threshold, source revision, verification log or employer claim gate.

[EmailAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/email_agent.py) drafts an email from applicant and faculty fields. The actual app does not send messages. [static/app.js](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/static/app.js) persists student profile and saved professors in browser localStorage, then passes selected data to the LLM endpoint to generate a draft.

## 3. Methodological and empirical shortcomings

[Columbia sample](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/runs/Columbia_parsed.json) has 72 faculty rows, two without email; [UCB sample](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/runs/UCB_parsed.json) has 134, twelve without email. Neither stores per-faculty source_url, exact quote, retrieved_at, verified_at, professor stable identity, active recruiting or funding status. An archived [UCLA extract](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/runs_old/UCLA_parsed.json) has 59 rows with all emails/links missing. These are committed outputs, not independent proof of identity or current employment.

The [planner](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/planner_agent.py) guesses a first-word .edu hostname on model failure rather than preserving UNKNOWN. The [searcher](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/search_agent.py) does not independently check returned link hosts or redirects against the asserted university before crawling. The [parser](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/parser_agent.py) silently discards failed chunks, deduplicates only on person name, lacks explicit typed validation and in its regex fallback can assign the first email found in a chunk to multiple people. Sending an email draft asserting a CV is attached is possible without proving an attachment exists.

## 4. Security and privacy failure modes

**Critical: untrusted path construction.** [main.py](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/main.py) calls only uni.strip() then uses that user-controlled value to build the .md and _parsed.json output file paths. There is no enforced directory containment or sanitized filename, authentication, job budget, input length or rate limiting on POST /scrape. Directory traversal in a constructed path can redirect writes outside the intended runs folder if a network caller reaches this endpoint. The default Uvicorn host is loopback, which limits default exposure, but does not secure other deployments.

**Critical: executable HTML sinks.** [main.py](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/main.py) injects serialized professor entries into JavaScript statements; the [faculty Jinja template](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/templates/uni_detail.html) renders the statement with the safe filter into an inline script. [static/app.js](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/static/app.js) builds innerHTML using untrusted professor properties stored locally. The faculty search no-match handler places raw search input in innerHTML; failed scrape errors are also interpolated into HTMLResponse without output escaping. These create credible browser injection surfaces; no browser exploit was executed.

Student profile details are stored unencrypted in localStorage and transmitted to an external model service for drafting. They are not isolated private evidence records; any successful same-origin script injection could access them. No credentials or personal applicant documents were accessed in this audit.

## 5. Review limitations, maintenance and transfer

The repository was created in January 2026; latest observed commit is May 3, 2026. Four commits were returned and no issue/PR was found. Python >=3.11, FastAPI, uvicorn, aiohttp, Crawl4AI, LangChain and OpenAI SDK are declared in [pyproject.toml](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/pyproject.toml). Tests were not executed: external API keys/browser dependencies and a controlled sandbox would be required. No live source recall, verified professor count, runtime security finding or e-mail deliverability has been measured.

Its useful architectural contribution is modular name normalization -> search -> retrieval -> extraction -> reviewed draft, **not** its authorization, trust, storage, scraping precision or freshness implementation. PhD Atlas should require institution-host/redirect validation, stable identities, exact source claims, scope/year, bounded authenticated worker execution, output encoding/CSP, safe storage, human review and proof of outreach before promoting data. Existing extracted faculties must not become verified recruiting leads.
