## 2. System objective and separation of responsibilities

PhD Fit is a private single-user Streamlit workspace that combines programme discovery, opportunity tracking, status/deadline verification, supervisor fit, applicant evidence, school portal credentials and CV/motivation-letter generation. The project makes a useful cost separation: Tavily-based discovery and deterministic monitoring versus explicit LLM calls for structured extraction, supervisor research, fit scoring and tailoring. It is **not** a public university admissions data service, multi-tenant account manager, verified funding registry or offer prediction engine.

## 3. Implemented data flow and algorithms

- [Monitor](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/services/opportunity_monitor.py) produces region/topic Tavily queries, ranks candidates using matching domain terms and stores `needs_manual_verification=True`. `likely_official` is primarily a domain/aggregator heuristic, not proof of university ownership. Position status is resolved by binding dates and `target_intake_year` with explicit evidence windows; prior-year application deadlines are allowed for next-year admissions and historical calls are not automatically promoted. Source URLs and refresh timestamps are stored with monitoring records.
- [SQLite](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/db.py) retains discovery history separately from promoted workspace positions; URL canonicalization and multi-signal dedup attempt to merge aliases conservatively while protecting separate user-owned positions. Data is spread across profiles, positions, discovered opportunities, supervisors, documents, base documents and portal accounts. The main `init_db` is idempotent on many table/column additions.
- [Fit ranking](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/scoring.py) sums bounded research/method/domain/feasibility dimensions and maps to 1–5 supervisor stars with evidence-count thresholds and to S–D opportunity scores. [OpenAI output](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/services/openai_service.py) is schema-validated through Pydantic and its final `total_score` is recomputed from components. LLM-generated supervisor paper citations nevertheless need direct verification.
- [Encryption](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/security.py) uses Fernet with `APP_SECRET_KEY` from the environment; when absent or invalid, saving encrypted portal passwords raises an exception rather than writing plaintext. [Document files](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/document_store.py) are saved locally with normalized filenames and time-stamped paths. [Fetcher](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/services/fetcher.py) accepts official URL/PDF, DOCX or text inputs.

## 4. Verified source-level failure cases

1. **Hard-eligibility gate is score-conditioned:** [`assign_position_level`](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/scoring.py) demotes an S/A grade only if `hard_gate_risks` is nonempty **and** the LLM-provided `eligibility_fit < 8`. If a required criterion is explicitly listed as unmet but the model still emits 8–15, a high total may remain S/A. A confirmed mandatory rejection should be a categorical gate independent of the subjective eligibility subscore.
2. **Official-source evidence is not equivalent to source ownership:** [`official_search_results`](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/services/opportunity_monitor.py) filters search results by same site only when same-domain results exist; otherwise upstream result lists may remain. The saved `likely_official` flag is driven by aggregator-domain heuristics. A ranking or status label therefore must not be presented as institution-confirmed without verifying URL authority and the source text.
3. **Silent migration failure:** [`init_db`](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/db.py) catches and suppresses any exception from the V6 monitoring migration, allowing the UI to start with partially updated records. Dependency errors and data-corruption errors are not equivalent. Use versioned migrations, transaction rollback, and actionable log/error visibility.
4. **Local-only authentication assumption:** [Streamlit gate](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/app.py) bypasses login entirely if `APP_LOGIN_PASSWORD` is unset. This is explicit for a private one-user setup but is unsafe if an operator deploys the workspace to a public address. No request-scoped isolation, rate limiting or multi-user authorization is demonstrated in this reviewed source.
5. **Manual data and private documents:** selected CV/transcripts and portal passwords are stored locally; [document files](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/document_store.py) persist on disk. There is no demonstrated encrypted-at-rest file store, retention/deletion lifecycle audit, malware/content validation or per-user storage controls. Normalizing filenames helps path hygiene but does not make public hosting suitable.
6. **Verification coverage:** [monitors tests](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/tests/test_monitoring_logic.py) check 2027 deadline cases, historical call separation, closed status and ISO parsing. [dedup tests](https://github.com/houwei1228/PhD_Fit/blob/1e95411ee0c2425c0ce77b658456e3110a7789f6/tests/test_deduplication.py) cover alias merge, distinct institutions and workspace ownership. These are useful synthetic fixtures but do not validate actual Tavily ranking, portal authentication, source freshness, PDF safety or current funded positions.

## 5. Cross-repository transfer opportunities

For the canonical research pipeline, adopt **discovery candidates → immutable evidence → manual verified field decisions → applicant fit → application record** and retain the distinction between source-owned facts and user-owned status/notes. Prefer typed official employer provenance, controlled date parsing with source year, and calibrated eligibility gates rather than a free-form model score. This project offers better date/domain policy than [Janjs historical scraper](https://github.com/Janjs/Web-Scraping-PhD-positions) and more conservative duplicate handling than the [NimaaaAI aggregator](https://github.com/NimaaaAI/Position-Aggregator) title-city collapse. It lacks the multi-user security and official institution verification required for a public system.

## 6. Reproduction and test plan

Use fake local SQLite databases and mocked Tavily/OpenAI responses. Add a regression for **unmet hard criterion with `eligibility_fit=15` and `total_score=96`** (must be rejected or marked ineligible regardless of S grade); same-domain absence resulting in third-party search results; malformed 2027 deadline input; failure halfway through a migration; and re-encryption/key rotation of stored portal secrets. Validate that nonofficial candidate status cannot be upgraded to officially verified by an LLM response without exact evidence references and an adjudicator.
