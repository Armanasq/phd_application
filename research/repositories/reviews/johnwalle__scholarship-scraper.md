## 1. Purpose and research relevance

A small Python scraper/cleaner and Flask listing prototype for scholarships. The README advertises multiple sites, normalized deadlines, CSV export and an extensible web UI. The actual implementation targets a single third-party listing page, `https://www.scholarshipsads.com/scholarships-in-italy`, and does not establish a pipeline of verified doctoral vacancies. The source covers mixed PhD, master's, bachelor's, postdoctoral and fellowship entries. It is relevant as an ingestion-failure case, not as an authoritative source of current funded opportunities.

## 2. Architecture and actual dataflow

`main.py` instantiates `Site1Scraper`, fetches the Italy listing, parses `h3 > a` links and adjacent `ul > li` text, then invokes `cleaners/clean_scholarships.py:clean_data`. That cleaner writes `data/clean/scholarships_cleaned.csv`. Neither the scraped raw records nor the result are written to `data/raw/scholarships.csv`.

In contrast, `app.py` imports `cleaner.py:clean_csv` at module initialization. That function reads the **committed** `data/raw/scholarships.csv`, extracts dates and writes the same cleaned CSV filename before the Flask request handler runs. The dashboard renders an in-memory DataFrame loaded from this separate raw fixture. Starting or refreshing the scraper does **not** refresh the dataset the dashboard uses, and importing the Flask module overwrites the cleaned output generated by `main.py`. The README's implied scrape-to-live-UI flow is therefore not implemented.

The two raw/clean CSV snapshots in the pinned tree have identical blob SHA `c91f75906f6adea5bf5231aa003ed46a8c33b2f4`. Their contents include 2025 and 2026 titles but contain no independently verified publisher snapshots or source-check timestamps. A third `scholarships_cleaned.csv` is committed and cannot be treated as current vacancy evidence.

## 3. Parsing, identity and funding semantics

The source parser walks every `h3` regardless of source-specific card identity, grabs the first anchor and the next sibling `ul`, and assigns one free-text value to each of funding, degree, eligibility and location based on substring matches. Absent fields remain missing. It does not inspect a destination university's primary admission/funding page; extraction from an aggregator's label such as `Fully Funded` is not an independently validated award component.

There are no stable issuer-specific vacancy IDs, deduplication, source version, crawl completeness, pagination handling, application cycle, currency, stipend duration, international tuition coverage, detailed eligibility rules, supervisor identity or raw-source hashes. The committed CSV mixes program levels, countries and historic cycles. Neither the dataset nor extraction justifies declaring an opportunity open or funded for a specific applicant.

## 4. Deadline and freshness correctness

Both cleaning modules use a regular expression `-([0-9]{1,2}[a-zA-Z]{3}[0-9]{4})` against the **link slug** rather than an authoritative deadline field. The suffix may describe a post's publication date or a page slug; most URLs do not match and become `NaT`. A successfully parsed slug date is still not an admission deadline without confirmation. Timezone, cutoff time and cycle are absent.

The scraper uses a single `requests.get` with neither timeout nor bounded retries, rate limit, sitemap contract, content size bound or pagination. A failed request returns an empty list, indistinguishable from a genuinely empty source. The application freezes its input DataFrame at module import, so there is no explicit refresh, missing-data signal or source-staleness warning.

## 5. Web interface and data-integrity risks

`app.py` filters the loaded DataFrame with `Series.str.contains(user_input)` and does not set `regex=False`. User-entered expressions are treated as regular expressions, allowing malformed expressions to raise exceptions and expensive patterns to consume CPU. The handler assumes `degree`, `location` and `funding` columns exist. Its deadline display compares a pandas datetime/NaT value with string `"NaT"`; this does not reliably identify missing deadlines.

The Flask entry point invokes `app.run(debug=True)` when run directly; this is suitable only for local development, not an exposed deployment. The template uses Jinja's default HTML escaping for cell text, but outbound links lack an explicit URL-scheme allowlist and use `target="_blank"` without `rel="noopener noreferrer"`. Neither authentication nor private applicant records are implemented.

## 6. Packaging, tests, maintenance and licensing

The tracked tree contains Python `__pycache__` bytecode files, two copies of the static CSV and no automated test directory or CI workflow. `requirements.txt` lists standard-library `csv` as an install requirement and does not declare the directly imported `Flask` or `lxml` packages; `dateutil` is imported via both cleaners without its own direct declared dependency. The README presents an MIT license, but no LICENSE file exists in the inspected tree, so reuse terms need independent confirmation.

The main branch's pinned commit is from 31 December 2025; at inspection, the repository's issue and pull-request collections returned no entries. No live request, package installation, Flask invocation, browser test or scraped-data verification was performed in this audit.

## 7. Repair priorities and controlled validation

**High:** connect ingestion and UI through one authoritative, atomically updated dataset or database, with last-successful-snapshot metadata and an explicit read-only fallback; never let application import rewrite fresh scraper output. Replace slug-derived dates with evidence-anchored official deadlines and preserve unknowns.

**Medium:** enforce parsed HTTPS source/redirect allowlists, timeouts, bounded retries, pagination/completeness results, per-record stable IDs, source hashes, change history and eligibility/funding field-level evidence. Treat scraper failures distinctly from empty authoritative results.

**Medium:** use safe literal filters (`regex=False`), validate schema on load, avoid debug serving in production and add fixtures/tests for source page changes, empty/failed scrapes, date ambiguity, refresh/read consistency, broken links and duplicate opportunities. Fix dependencies and establish the actual license before code reuse.

## 8. Transfer to the PhD application research system

Keep the simple separation between source-specific extraction, normalization and presentation, but not its current implementation or data. The existing research architecture already distinguishes opportunity leads from verified employer records; this scraper demonstrates why both **source completeness** and **data consumption provenance** matter. A third-party aggregator record should enter as a dated discovery observation, not a verified PhD position, deadline or funding guarantee. No external rows were imported into the canonical opportunity dataset from this audit.
