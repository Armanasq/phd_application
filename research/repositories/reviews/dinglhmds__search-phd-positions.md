## 1. Identity, scope, and scientific boundary

The 75-file Python project implements a student-facing professor directory search and a model-assisted email drafting UI. It is not a verified inventory of funded doctoral positions, current PI recruiting availability, scholarship admissions or legally binding stipend terms. The latest inspected commit is May 3, 2026. No license file, CI workflow or reproducible active automated test suite was identified in the pinned repository tree; no issues/PRs were returned. The project includes two current sample faculty JSON files, archived samples and historical UI prototypes. The README describes a Python 3.11/FastAPI, SerpApi, Crawl4AI, SiliconFlow LLM workflow.

## 2. Architecture and operational dataflow

The [FastAPI entry point](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/main.py) receives a university name, uses [PlannerAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/planner_agent.py) to resolve an alias or infer a domain, [SearchAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/search_agent.py) to query Google via SerpApi, [CrawlerAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/crawler_agent.py) to fetch the **first returned** page, and [ParserAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/parser_agent.py) to extract professor name/title/research areas/email/link in 8,000-character chunks with a maximum of eight threaded LLM calls. It saves one parsed JSON file per input university. If the file exists, a new crawl is skipped with no TTL, evidence versioning or re-verification.

[EmailAgent](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/email_agent.py) drafts a personalized letter using applicant and selected faculty fields. This active app does not send the email. Browser [static/app.js](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/static/app.js) retains profile and selected professors in localStorage. The alias file [universities.yaml](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/configs/universities.yaml) contains 274 entries at this commit; the development guide's 800+ count is stale.

## 3. Data, provenance, and extraction accuracy

[Columbia sample](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/runs/Columbia_parsed.json) has 72 faculty records (2 missing emails); [UCB sample](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/runs/UCB_parsed.json) has 134 (12 missing emails). These are **committed extracts**, not independently verified faculty appointments. Neither JSON file stores the exact person-level retrieved URL, quoted evidence span, content hash, retrieval/verification time, active PhD recruitment, funding scope or applicable cycle. An archived [UCLA sample](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/runs_old/UCLA_parsed.json) has 59 entries, all without recorded email or link.

The [planner](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/planner_agent.py) falls back to a guessed .edu domain when the model lookup fails; [search](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/src/agents/search_agent.py) does not enforce host/redirect authority after retrieval. Parser failed chunks are silently omitted; a regex fallback can attribute the first found email in a chunk to multiple unrelated names; deduplication is by display name alone, and JSON schema validation is not demonstrated.

## 4. Security, privacy, and trust boundaries

In [main.py](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/main.py), unauthenticated POST /scrape derives both output paths directly from user-entered university text after strip() only, without enforcing canonical path containment, safe output IDs, traversal rejection, size limits or request budgets. If network-exposed, it provides a credible unsafe local-file-write route; its default loopback binding reduces default reachability but does not remove the flaw. HTML error responses interpolate exception strings without escaping.

The [faculty template](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/templates/uni_detail.html) uses the Jinja safe filter on serialized JavaScript statements built with untrusted professor fields. [static/app.js](https://github.com/dinglhmds/Search-PhD-Positions/blob/0fe7c7c294bd549800b71856435702ba6e4098f0/static/app.js) creates HTML with innerHTML from model-extracted professor attributes, and the faculty search's no-result message concatenates raw user input into innerHTML. These are credible XSS surfaces, not demonstrated exploits. Applicant personal fields are saved in localStorage and transmitted to a third-party LLM during draft creation; no evidence of an encrypted applicant vault or authorization gate exists.

## 6. Comparison, failure modes and source independence

Compared with source-scoped admissions systems such as dxeledx/PhdInfoHub, this project has modular search/crawl/parse separation but no per-claim literal quotation, applicant scope, date revision history or current official employer notice binding. Its cached faculty list is not a recruiting feed. A manually curated professor directory or a second scraper pointing to the same faculty page is not independent evidence of admissions. The absence of a current vacancy cannot be inferred from a failed or empty extraction; missing data must be explicit.

## 7. Candidate-specific action and integration decision

Retain adapter design as a reference for a future **candidate discovery** stage only: institution alias normalization, bounded search, source capture, typed faculty extraction and human-approved draft generation. Rebuild output storage with server-generated opaque IDs and path containment; validate fetched host and redirects; encode HTML/JavaScript and apply CSP; keep private applicant data out of untrusted DOM; normalize faculty identities by official links; attach exact governing source URL/span, SHA, retrieved_at and verified_at; independently establish PI recruiting, applicant class, tuition and funding; and never auto-send email. Do **not** import its sample JSON as verified people, vacancies or funding.
